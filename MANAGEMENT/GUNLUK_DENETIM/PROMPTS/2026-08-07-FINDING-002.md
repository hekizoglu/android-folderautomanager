# FINDING-002 — Vendor prefix sınırı çözüm promptu

## Amaç
`CategorySuggestionEngine.knownVendorPrefixOf()` ve ilgili AppClassifier vendor kontrollerinde ham `startsWith()` kullanımının kardeş paketleri yanlış üretici olarak kabul etmesini engelle.

## Kanıt
Mevcut `CategorySuggestionEngine.kt` içinde:
```kotlin
return KNOWN_VENDOR_PREFIXES.firstOrNull { lowerPkg.startsWith(it) }
```
Bu nedenle örneğin `com.amazonian.reader` gerçek `com.amazon` paketiymiş gibi vendor sinyali alabilir. Aynı risk `com.googlefake`, `com.spotifyhelper` vb. için geçerlidir.

## Kapsam
Önce:
- `CategorySuggestionEngine.kt`
- `AppClassifier.kt`
- vendor ile ilgili testler
- `KeywordDatabase.kt`
- `MANAGEMENT/LEARNINGS.md`

## Uygulama
1. Vendor prefix karşılaştırmasını paket segment sınırına bağlayan tek bir helper oluştur veya mevcut helper'ı güvenli hale getir.
2. Geçerli eşleşme:
   - `packageName == prefix`
   - veya `packageName.startsWith("$prefix.")`
3. `com.amazonian` → Amazon kabul edilmemeli.
4. `com.amazon.app` → Amazon kabul edilmeli.
5. `com.amazon` → Amazon kabul edilmeli.
6. Benzer sibling prefix'lerde uzun prefix'in kısa prefix tarafından yanlış yakalanmaması için deterministik en uzun geçerli prefix'i tercih et.
7. AppClassifier ve CategorySuggestionEngine aynı vendor boundary helper/policy'yi kullanmalı; iki ayrı sınır algoritması oluşturma.
8. Uygulama adı vendor sinyali kullanılıyorsa düz `contains()` yerine ürün kararına uygun token sınırı uygula. `MetaMask` gibi gerçek marka adı içeren uygulamaların yanlışlıkla yalnızca `meta` substring'i nedeniyle Meta vendor sinyali almasını engelle.

## Test kabul kriterleri
En az şu paketler test edilmeli:
- `com.amazon` → match
- `com.amazon.app` → match
- `com.amazonian.reader` → no match
- `com.google.android.gm` → match
- `com.googlefake.tool` → no match
- `com.spotify.music` → match
- `com.spotifyhelper.app` → no match

Uygulama adı örnekleri:
- `MetaMask` → yalnız `meta` substring'ine dayanarak vendor match üretmemeli
- `Meta` → token olarak match edilebilir
- `My Meta App` → ürün kararına göre açık token davranışı test edilmeli
