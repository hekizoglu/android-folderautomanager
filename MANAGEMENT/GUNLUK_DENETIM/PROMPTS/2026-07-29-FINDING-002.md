# AppOrganizer Hata Düzeltme Görevi — FINDING-002

## Rol

Sen kıdemli Android/Kotlin mühendisisin. AppOrganizer üretici eşleştirme mantığındaki paket segmenti ve uygulama adı kelime sınırı hatasını düzelt.

## Doğrulanmış Sorun

- **Bulgu kimliği:** FINDING-002
- **Önem:** Orta
- **Kategori:** Mantık hatası / yanlış üretici klasörü / sahte pozitif
- **Etkilenen dosyalar:**
  - `app/src/main/java/com/armutlu/apporganizer/domain/usecase/classify/AppClassifier.kt`
  - `app/src/main/java/com/armutlu/apporganizer/domain/usecase/classify/CategorySuggestionEngine.kt`
  - İlgili test dosyaları

## Kanıt

1. `AppClassifier.classifyByManufacturerPrefix()` paket eşleşmesini `pkg.startsWith(prefix)` ile yapıyor.
2. `CategorySuggestionEngine.knownVendorPrefixOf()` aynı şekilde `lowerPkg.startsWith(it)` kullanıyor.
3. Bu mantık paket segment sınırını kontrol etmiyor:
   - `com.amazonian.reader` yanlışlıkla `com.amazon` üreticisi sayılabilir.
   - `com.googlefake.tool` yanlışlıkla `com.google` üreticisi sayılabilir.
   - `com.spotifyhelper.app` yanlışlıkla `com.spotify` üreticisi sayılabilir.
4. `AppClassifier` uygulama adı tarafında `lowerName.contains(mfr)` kullanıyor.
5. Bu nedenle `MetaMask`, `Metaverse Tools`, `Amazonian Reader` gibi isimler gerçek üretici ilişkisi olmadan `meta` veya `amazon` üretici sinyali oluşturabilir.
6. Özellikle `MetaMask`, KeywordDatabase içinde FINANCE sinyali taşırken uygulama adı üretici kontrolü daha önce çalıştığı için yanlışlıkla CAT_META'ya düşme riski taşır; exact/remote/Android category sinyali bulunmayan varyantlarda bu deterministiktir.

## Kullanıcı Etkisi

- Katalogda bulunmayan veya yeni uygulamalar yanlış marka klasörüne yerleştirilebilir.
- Benzer paket önerileri yanlış vendor kardeşliği kurabilir.
- Yanlış üretici sinyali keyword sinyalinden önce döndüğü için daha doğru kategori kanıtını ezebilir.
- Kullanıcı yanlış klasörleri sürekli elle düzeltmek zorunda kalabilir.

## Kök Neden

Üretici eşleşmesi metin prefix/substr eşleşmesi olarak uygulanmış; paket adının noktayla ayrılan segment yapısı ve uygulama adının token sınırları dikkate alınmamış.

## İstenen Çözüm

1. Ortak bir paket prefix yardımcı fonksiyonu oluştur veya aynı güvenli kuralı iki yerde uygula:

```kotlin
private fun matchesPackagePrefix(packageName: String, prefix: String): Boolean {
    val normalized = packageName.lowercase(Locale.ROOT)
    return normalized == prefix || normalized.startsWith("$prefix.")
}
```

2. `AppClassifier` ve `CategorySuggestionEngine` aynı boundary kuralını kullanmalı.
3. Uygulama adı üretici eşleşmesinde düz `contains()` kaldırılmalı.
4. Üretici adı yalnız şu durumlarda eşleşmeli:
   - tam ad
   - başında/sonunda harf-rakam olmayan token sınırı
   - açıkça tanımlanmış marka phrase'i
5. `MetaMask` içindeki `meta` üretici eşleşmesi olmamalı.
6. Türkçe locale yalnız kullanıcı görünen uygulama adını normalize ederken kullanılmalı; paket adı her zaman `Locale.ROOT` ile normalize edilmeli.
7. Mümkünse üretici prefix listesi tek bir ortak kaynağa taşınmalı; `AppClassifier` ve `CategorySuggestionEngine` içinde iki ayrı kopya zamanla ayrışmamalı.
