# Günlük Denetim Bulgusu — 2026-08-09 — Folder page strip ayarı aynı ekranda reaktif değil

## Önem
Orta. Veri kaybı veya crash riski yok; ancak kullanıcı klasör sayfası bilgi bandını kapattığında sayfa kapasitesi ve görünüm aynı composition içinde eski değerde kalabiliyor.

## Kanıt
`HomeScreen.kt` içinde:

```kotlin
val folderPageStripEnabled = remember(context) { AppPrefs.isFolderPageStripEnabled(context) }
val folderCapacity = remember(
    availableHeightDp,
    effectiveFolderSizeDp,
    screenColumns,
    folderPageNotificationsEnabled,
    folderPageStripEnabled
) {
    HomeLayoutMath.folderCapacity(
        availableHeightDp = availableHeightDp,
        folderSizeDp = effectiveFolderSizeDp,
        columns = screenColumns,
        infoPanelVisible = folderPageNotificationsEnabled && folderPageStripEnabled
    )
}
```

`HomeScreenFolderPager.kt` içinde de:

```kotlin
var pageStripEnabled by remember(context) {
    mutableStateOf(AppPrefs.isFolderPageStripEnabled(context))
}
```

`HomeScreen.kt`'nin SharedPreferences listener'ında `KEY_FOLDER_PAGE_STRIP_ENABLED` için bir state güncellemesi bulunmuyor. Bu nedenle:

- Ayarlar ekranından bandı açıp kapatma, mevcut HomeScreen composition'ında hemen yansımıyor.
- Folder page içindeki kapatma ikonu yalnız kendi local `pageStripEnabled` state'ini güncelliyor; üst seviyedeki `HomeScreen` hesapladığı `folderCapacity` eski değerde kalabiliyor.
- Bandın kapatılmasından sonra klasör grid'inin kapasitesi aynı composition içinde bir sonraki dış tetikleyiciye kadar değişmeyebilir.

## Kök neden
Aynı SharedPreferences anahtarının üç ayrı tüketicisi var, fakat tek bir reaktif state zinciri yok:

1. HomeScreen kapasite hesabı
2. FolderGridPage görünürlük state'i
3. Settings ekranı yazımı

Yazma ve tek seferlik okuma var; reaktif tüketim eksik.

## Kullanıcı etkisi
- Kullanıcı bandı kapatır.
- Band görünümü kaybolsa da klasör sayfa kapasitesi eski panel yüksekliğini hesaba katabilir.
- Daha fazla klasörün aynı sayfaya sığması beklenirken sayfa sayısı/yerleşim gecikmeli güncellenebilir.
- Ayarlar ekranından değişiklik yapıp geri dönünce eski görünümle karşılaşılabilir.

## Neden bu denetim turunda otomatik düzeltilmedi
Bu değişiklik Compose state ve sayfa planı davranışına dokunuyor. Gradle/ADB doğrulaması mevcut değildi; doğrulanmamış UI/state değişikliği main'e yazılmadı.

## Uygulama talimatı
1. `HomeScreen.kt` seviyesinde:
   - `var folderPageStripEnabled by remember { mutableStateOf(AppPrefs.isFolderPageStripEnabled(context)) }` state'i oluştur.
   - Mevcut SharedPreferences listener'a `KEY_FOLDER_PAGE_STRIP_ENABLED` case'i ekle.
2. `folderPageStripEnabled` değerini `FolderGridPage` çağrısına parametre olarak geçir.
3. `HomeScreenFolderPager.kt` içinde `remember(context)` ile ayrı bir kaynak state tutmak yerine üstten gelen state'i kullan.
4. Kapatma ikonunun callback'i iki işi birlikte yapmalı:
   - `AppPrefs.setFolderPageStripEnabled(context, false)` yazmalı.
   - Üst seviyedeki state'i güncelleyecek callback'i tetiklemeli.
5. `folderCapacity` hesabı yalnız tek reaktif `folderPageStripEnabled` state'ine bağlanmalı.
6. `pageStripEnabled` ile `folderPageNotificationsEnabled` kavramlarını ayırmaya devam et; notification row toggle mantığını bozma.
7. Yeni persistence, migration, navigation veya dependency ekleme.
