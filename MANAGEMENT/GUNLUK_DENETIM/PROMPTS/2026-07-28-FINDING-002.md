# AppOrganizer Hata Düzeltme Görevi

## Rol

Sen kıdemli Android/Kotlin ve Jetpack Compose mühendisisin. AppOrganizer uygulama çekmecesindeki bayat ikon cache hatasını en küçük güvenli değişiklikle düzelt.

## Doğrulanmış Sorun

- **Bulgu kimliği:** FINDING-002
- **Önem:** Orta
- **Güven seviyesi:** %99
- **Kategori:** Compose state / ikon cache / paket–ikon tutarlılığı
- **Belirti:** Bir uygulama güncellendiğinde çekmecedeki `NiagaraAppRow` eski uygulama ikonunu göstermeye devam edebilir. Process veya global LRU cache temizlenene kadar ikon yenilenmeyebilir.
- **Kullanıcı etkisi:** Uygulama adı ve paket doğru olduğu halde ikon eski kalabilir. Kullanıcının daha önce bildirdiği “uygulama doğru, görsel eski/yanlış” sınıfındaki problemlere doğrudan zemin hazırlar.

## Kanıt

### 1. Cache anahtarı güncelleme zamanını içermiyor

Dosya:
`app/src/main/java/com/armutlu/apporganizer/presentation/ui/launcher/AllAppsDrawerUtils.kt`

Mevcut fonksiyon:

```kotlin
@Composable
internal fun rememberAppIcon(packageName: String, iconPackPkg: String = ""): ImageBitmap? {
    val context = LocalContext.current
    val cacheKey = if (iconPackPkg.isEmpty()) "${packageName}_96" else "${packageName}_96_$iconPackPkg"
    return produceState<ImageBitmap?>(initialValue = iconCacheInternal[cacheKey], packageName, iconPackPkg) {
        // ...
    }.value
}
```

Cache anahtarı ve `produceState` key’leri yalnızca paket adı ile icon-pack paketini içeriyor. Uygulama aynı packageName ile güncellendiğinde key değişmiyor.

### 2. Çağıran AppInfo güncelleme zamanına sahip

Dosya:
`app/src/main/java/com/armutlu/apporganizer/presentation/ui/launcher/NiagaraComponents.kt`

Mevcut çağrı:

```kotlin
val icon = rememberAppIcon(app.packageName, iconPackPkg)
```

`AppInfo` içinde `lastUpdatedTime` mevcut ve aynı çekmece dosyasındaki son kullanılanlar/favoriler/bildirim satırlarında cache anahtarına zaten ekleniyor.

### 3. Repo mimari kuralı

`MANAGEMENT/LEARNINGS.md` içinde ikon cache anahtarının her yerde `lastUpdateTime` içermesi gerektiği açıkça kayıtlıdır. Mevcut `rememberAppIcon` bu kurala uymuyor.

## Kök Neden

Global ikon LRU cache’i paket adı bazlı çalışıyor. Android uygulama güncellemesinde paket adı değişmediği için eski bitmap aynı anahtardan bulunuyor. Compose tarafında `produceState` de yeniden başlamıyor; dolayısıyla yeni ikon diskten/PackageManager’dan tekrar yüklenmiyor.

## Sınırlar

- Cache sistemini yeniden tasarlama.
- Global LRU cache sınıfını değiştirme.
- Package change receiver veya veritabanı akışına dokunma.
- Yeni dependency ekleme.
- İkon boyutunu veya görünümünü değiştirme.
- İlgisiz refactor yapma.
- versionCode/versionName artırma; bu günlük hata düzeltme doğrulamasıdır.

## İstenen Çözüm

1. `rememberAppIcon` fonksiyonuna `lastUpdatedTime: Long` parametresi ekle.
2. Cache anahtarını aşağıdaki bilgileri içerecek şekilde üret:
   - packageName
   - ikon boyutu (`96`)
   - lastUpdatedTime
   - varsa iconPackPkg
3. `produceState` key’lerine `lastUpdatedTime` ekle. Tercihen doğrudan `cacheKey` kullan.
4. `NiagaraAppRow` çağrısını şu şekilde güncelle:

```kotlin
val icon = rememberAppIcon(
    packageName = app.packageName,
    lastUpdatedTime = app.lastUpdatedTime,
    iconPackPkg = iconPackPkg,
)
```

5. Repo genelinde `rememberAppIcon(` araması yap; başka çağıran varsa aynı şekilde gerçek `lastUpdatedTime` ile güncelle.
6. Default `lastUpdatedTime = 0L` ekleyerek hatayı gizleme. Çağıranın gerçek zamanı sağlamasını zorunlu tut.

## Önerilen Anahtar Formatı

```kotlin
val cacheKey = if (iconPackPkg.isEmpty()) {
    "${packageName}_96_${lastUpdatedTime}"
} else {
    "${packageName}_96_${lastUpdatedTime}_$iconPackPkg"
}
```

Mevcut diğer ikon composable’larının formatıyla tutarlılığı kontrol et; repo standardı farklılaşmışsa aynı standardı kullan.

## Kabul Kriterleri

- Uygulama güncellenince `lastUpdatedTime` değişimi cache anahtarını değiştirir.
- `produceState` yeni ikon yükleme işini yeniden başlatır.
- Aynı packageName için eski bitmap yanlışlıkla kullanılmaz.
- Icon pack davranışı bozulmaz.
- Compile, unit test, lint ve assembleDebug başarılıdır.
- Değişiklik yalnızca gerekli fonksiyon imzası ve çağrı noktalarıyla sınırlıdır.

## Rollback

`rememberAppIcon` imzasını eski haline döndürüp çağrı noktalarındaki `lastUpdatedTime` parametresini kaldırmak yeterlidir. Kalıcı veri veya migration etkisi yoktur.
